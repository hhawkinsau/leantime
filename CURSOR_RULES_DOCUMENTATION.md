# Cursor Rules Documentation

**Date**: September 9, 2025  
**Author**: Hudson Hawkins (GVM - Global Vision Media)  
**Purpose**: Documentation for Cursor Rules generated from CLAUDE.md

## Overview

This document describes the Cursor Rules that have been generated for the Leantime project based on the comprehensive CLAUDE.md file. These rules provide AI assistance with understanding the project architecture, coding standards, and development practices.

## Generated Rules

The following Cursor Rules have been created in the `.cursor/rules/` directory:

### 1. project-overview.mdc
- **Type**: Always Applied
- **Purpose**: Core project information and architecture overview
- **Content**: Technology stack, key directories, domain structure, development commands

### 2. architecture-patterns.mdc
- **Type**: Always Applied
- **Purpose**: Architecture patterns and layer enforcement rules
- **Content**: Layer architecture, data layer patterns, HTTP layer, event system, service layer

### 3. coding-standards.mdc
- **Type**: Always Applied
- **Purpose**: Coding standards and best practices
- **Content**: Code style, type safety, error handling, datetime handling, security, performance

### 4. frontend-development.mdc
- **Type**: File-specific (JS, TS, CSS, template files)
- **Purpose**: Frontend development guidelines and patterns
- **Content**: HTMX usage, CSS guidelines, JavaScript requests, template system, performance

### 5. plugin-system.mdc
- **Type**: Manual application
- **Purpose**: Plugin system architecture and development guidelines
- **Content**: Plugin architecture, types, registration, loading, integration points, license management

### 6. testing-guidelines.mdc
- **Type**: Manual application
- **Purpose**: Testing strategy and guidelines
- **Content**: Testing tools, strategy, commands, failure handling, test organization

### 7. api-development.mdc
- **Type**: Manual application
- **Purpose**: API development guidelines and patterns
- **Content**: JSON-RPC API, authentication, development patterns, security, frontend usage

### 8. configuration.mdc
- **Type**: Manual application
- **Purpose**: Configuration management and environment setup
- **Content**: Configuration files, Laravel config, Redis config, environment variables, plugin config

### 9. development-workflow.mdc
- **Type**: Manual application
- **Purpose**: Development workflow and task approach guidelines
- **Content**: Task approach hierarchy, context management, development commands, CLI commands

## Rule Application

- **Always Applied Rules**: Automatically applied to every AI interaction
- **File-specific Rules**: Applied when working with specific file types
- **Manual Rules**: Applied when relevant to the specific task or when explicitly requested

## Benefits

These rules provide:
- Consistent understanding of project architecture
- Enforced coding standards and best practices
- Clear guidelines for frontend development
- Comprehensive testing strategies
- Proper API development patterns
- Configuration management guidance
- Efficient development workflows

## Maintenance

These rules should be updated when:
- Project architecture changes significantly
- New coding standards are adopted
- Development workflows evolve
- New technologies are integrated

The rules are based on the current state of the CLAUDE.md file and should be kept in sync with any updates to that documentation.
